# Stealth Render Studio

Headless-браузер як локальний сервіс із веб-інтерфейсом: рендер будь-якої сторінки
через Playwright, запис і відтворення дій користувача, антидетект-режими та
конфігуратор. Побудовано за сесію як дослідницький інструмент, тож код тримає
багато напрацювань про те, як антиботи (зокрема Cloudflare) детектують автоматизацію.

## Призначення: тестовий стенд

Це **тестовий стенд** для емпіричної перевірки, **який конфіг проходить різні
перевірки на сайтах** (Cloudflare, антиспам форм, фінгерпрінт-детектори тощо).
Сенс — зручний інтерфейс, де можна **вмикати/вимикати окремі налаштування**
(рушій, stealth-прапорці, фінгерпрінт, людська поведінка) через конфігуратор і
**швидко перевіряти** результат: відкрити сторінку, відтворити сценарій і одразу
побачити фінальний скрин + лог. Нічого, що допомагає пройти перевірку, не
захардкоджено — усе винесено в опції/пресети, щоб калібрувати комбінації.

## Швидкий старт

```bash
npm install                 # + postinstall автопатчить camoufox-js
npm run fetch-camoufox      # завантажує бінарник Camoufox (~1.3 ГБ, ОДИН раз)
npm start                   # http://localhost:3000
```

- Потрібен встановлений **Google Chrome** (Chromium-режим використовує `channel: 'chrome'`).
- Потрібен **Postgres** (Postgres.app на macOS). За замовчуванням:
  `postgres://<user>@localhost:5432/playwright_demo`. Перевизначається через `DATABASE_URL`.
  Якщо БД недоступна — сценарії живуть у пам'яті процесу сервера (до його перезапуску).
- Змінні оточення (`lib/config.js`): `PORT` (3000), `DATABASE_URL`, `PROFILE_FILE`
  (`./profile.json`), `UPLOAD_DIR` (`./uploads`), `HOST` (`127.0.0.1`), `ALLOWED_HOSTS`.
- **Безпека локального сервісу:** сервер слухає ЛИШЕ `127.0.0.1` і перевіряє `Host`
  (`lib/guard.js`: лише localhost/127.0.0.1/[::1] — захист від DNS-rebinding) та `Origin`
  змінних запитів (крос-сайтовий POST → 403). `/upload` приймає лише
  `application/octet-stream` + `x-filename` (інакше 415). Доступ із мережі — явно:
  `HOST=0.0.0.0 ALLOWED_HOSTS=192.168.1.5,mymac.local npm start`. Тестовий екземпляр поруч із робочим:
  `PORT=3101 DATABASE_URL=postgres://nobody@127.0.0.1:1/none PROFILE_FILE=/tmp/p.json npm start`
  (недосяжна БД → режим у пам'яті, реальні сценарії не чіпаються).

## Архітектура

```
Браузер (UI) ──HTTP──> Express (server.js) ──Playwright──> Chromium | Camoufox
                            │
                            └── Postgres (pages) + файли (uploads/)
```

- **server.js** — тонка точка входу: конфіг → профіль → рушій → БД → `app.listen`
  (+ коректне завершення на SIGTERM/SIGINT).
- **lib/*.js** — бекенд-модулі БЕЗ побічних ефектів при імпорті (усе через явні
  `create*/init*`): `config` (env), `profile` (дефолти, `applyProfilePatch`, cookies,
  profile.json), `stealth` (init-скрипт + ледаче підвантаження stealth-плагіна),
  `engine` (`launchArgs/launchFlags`, single-flight запуск, пул з поколіннями,
  `relaunchBrowser` з хуками `onBeforeRelaunch`), `semaphore`, `nav` (Cloudflare-aware
  goto, `isChallenge`, settle-очікування), `human`, `dom`, `replay` (цикл відтворення),
  `logs` (лог-рядки з реальних прапорців), `db` (схема + репозиторії), `uploads`,
  `http` (`asyncHandler` + error middleware), `app` (`createApp(deps)`),
  `session` (SessionStore живих сесій), `capture` (hit-test + опис елемента +
  лічильники локаторів), `live` (живі сесії запису).
- **Спільні ізоморфні модулі** (без Node-імпортів, роздаються браузеру як ES-модулі
  через білий список `GET /lib/<name>.js`, `SHARED_LIBS` у `lib/app.js`): `steps`, `coords`,
  `locators`, `textTemplate`, `errText` (чищення помилок Playwright: ANSI, «Call log», net::ERR_* →
  українською; тим самим модулем чистить і сервер — `errorHandler`, `/live`, `/replay`), `transfer`
  (бандл експорту/імпорту пресетів і сценаріїв, план конфліктів назв — див. «📦 Експорт / імпорт»).
- **routes/*.js** — HTTP-роути (render, replay, pages, recordings, presets, upload,
  profile, health, live, transfer); залежності приходять через `createApp(deps)`. Сховище сценаріїв
  у памʼяті (без БД) — спільне `d.pagesMem` (pages + transfer).
- **public/** — фронтенд без збірки (див. розділ «Фронтенд» нижче): `index.html` (лише
  семантична розмітка і точки монтування), `css/*.css`, `js/*.js` — ES-модулі.
- **scripts/patch-camoufox.mjs** — автопатч бібліотеки camoufox-js (див. нижче).

### Теплий пул браузера
Браузер запускається ОДИН раз і живе весь час. На кожен запит береться готовий
**ізольований контекст** із пулу (`POOL_SIZE = 3`), тож `newContext` ~0 мс. Кожен
контекст використовується рівно раз → ізоляція сесій. Пул поповнюється у фоні.

### Два рушії (перемикач у конфігураторі)
| Рушій | Коли | Швидкість |
|---|---|---|
| **Chromium** (дефолт) | звичайні сайти, скриншоти, масовість | швидко, теплий пул |
| **Camoufox** (Firefox-антидетект) | жорсткий Cloudflare / DataDome | повільніше, але **проходить** |

Camoufox драйвиться тим самим Playwright (через протокол Juggler, а не CDP). У цьому
режимі наші Chromium-патчі НЕ застосовуються — Camoufox має власний антидетект на
рівні C++ рушія.

## Можливості (UI)

- **Рендер URL** → fullPage-скриншот + метадані + витягнутий текст. Навігація
  стійка до Cloudflare (`gotoSmart`: domcontentloaded + очікування зникнення
  «Just a moment…», мовно-незалежно по DOM-маркерах).
- **Таби скрінів** — результати прогонів/записів (лише перегляд): ліміт 12, закриття,
  статус-крапка (зелена / ⚠ запасний шлях / червона / зупинено), підпис з НАЗВОЮ Дії як у
  сайдбарі («Форма · до «Логін»», «· «Дія 3»», «· усі Дії (N)», «· лише URL»), 1:1 / по ширині, ↗ і ⬇.
- **Три рівні сценаріїв:** `Сценарій → Дія → під-дія`
  - **Сценарій** — стартовий URL + список Дій. Кнопка **▶ Старт** відкриває URL і
    послідовно відтворює всі Дії (накопичувальний ланцюг). Працює навіть без Дій
    (просто відкриває URL).
  - **Дія** — один запис (від старту до стопу запису). Згортається, перейменовується,
    видаляється. ▶ на Дії виконує ланцюг до неї включно.
  - **під-дія (крок)** — клік / текст / клавіша / select / файл / прокрутка (legacy: рух
    миші). Редагується в модалці ✎, вимикається ⏸, переставляється ↑↓, видаляється
    (з «Скасувати»); два сусідні текстові кроки зливаються ⤵; ⏱ пауза після кроку.
- **Живий запис** (⏺ Записати / ⏺ Дописати) — сервер тримає відкриту сторінку, у переглядачі
  її живий кадр: клік/друк/колесо/жести йдуть у сторінку, кожна дія стає кроком v2 із
  семантичною ціллю (див. «Живий запис і кроки v2»). Запису на статичному скріні більше немає.
- **Рандом для тексту** — шаблон у тексті кроку: `{d}` — цифра, `{l}` — літера, `{{` — «{»
  (чипи в редакторі кроку; старі 🔒/🎲-кроки показуються як `{d}`/`{l}`).
- **Завантаження файлів** — під-дія `file`: файл вантажиться на сервер, при
  відтворенні підставляється напряму в `input[type=file]` (по всіх фреймах, у т.ч.
  iframe) через `setInputFiles` — надійніше за `filechooser`.
- **Лог-консоль** — показує життєвий цикл: рушій, браузер (reuse/launch), контекст,
  що підставлено (fingerprint/cookies/stealth), CF-статус, кроки відтворення (стрім).
- **Конфігуратор** (⚙) — модалка з лівим сайд-меню категорій; редагує ВСЕ (див.
  окремий розділ нижче). Жодне анти-детект рішення не захардкоджено.
- **Людська поведінка** при відтворенні: криві рухи миші, змінні затримки, друк по
  буквах, випадкові скроли-«роздивляння».
- Усе зберігається в **Postgres** (таблиця `pages`, Дії як JSONB). Без БД сценарії
  живуть у **памʼяті процесу сервера** (`/pages` → `db:false, memory:true`): переживають
  перезавантаження вкладки, але не перезапуск сервера (бейдж «💾 лише в памʼяті»).

## Фронтенд (public/)

Без збірки й CDN: `<script type="module" src="/js/app.js">`, спільні ізоморфні модулі
імпортуються як `../../lib/x.js` (у браузері це `/lib/x.js` з білого списку `SHARED_LIBS`) —
логіку НЕ дублюємо. Модулі НЕ чіпають DOM під час імпорту → чиста логіка тестується в node:test.
Тексти UI — українською; темна тема на CSS-змінних (`css/base.css`): `--bg #0f1115`, `--accent
#4f7cff` (рамки/фокус), фони кнопок під білим текстом — `--accent-btn` / `--danger-btn` (≥ 4.5:1).

### Каркас
`app.js`, `css/base.css`: висота = екран, жодної горизонтальної прокрутки (перевіряється на 390 px).
- **< 900 px** — одна панель за раз «Сценарії | Перегляд | Логи» (нижня навігація, бейджі «новий
  скрін»/«помилки»; старт запису → автоматично «Перегляд»; `emit('ui:pane', name)`).
- **≥ 900 px** — перегляд+логи зліва, сценарії справа (ширину сайдбара можна тягнути).
- Хедер: бейджі `/health` («💾 лише в памʼяті», «● LIVE ×N», «⚠ сервер недоступний»), чип конфігу
  «🧩 Chromium · 📋 Ashby» / «· кастом» / «● змінено» (клік — конфігуратор), бейдж збереження, 📥 Імпорт / 📤 Експорт усього застосунку (пресети + сценарії;
  < 1100 px — лише іконки).

### Живий запис (UX)
Запису на статичному скріні більше НЕМАЄ: скріни в табах — лише результати.
1. **Вхід:** на картці сценарію «⏺ Записати» (префікс = усі Дії → НОВА Дія), «▾ → ⏮ З початку
   (лише URL, нова Дія в кінці)»; на кожній Дії «⏺» = «Дописати» (префікс до неї включно, кроки
   йдуть у неї). Нова Дія називається «Дія N» **у межах сценарію** (`nextRecName`: max N + 1, не
   менше кількості Дій + 1); `rec.id` — глобальний (`state.recCounter`, потрібен для reattach).
2. **Відкриття:** оверлей «Відкриваю … відтворюю N кроків k/N», у сайдбарі ▶/✓/✗ кроків префікса.
   Якщо в ланцюгу є крок із побічним ефектом (сабміт / ⏳) — спершу `<dialog>`-підтвердження
   (етичне обмеження: не спамимо форми). Помилки відкриття — людським текстом (`humanError`).
3. **Тулбар** (`#recToolbar`): ● LIVE / ⏸ ПАУЗА, рушій, «⏺ «Дія N» · Сценарій»; URL + ◀ ▶ ⟳
   (навігація НЕ записується); ⏸ Пауза запису (ввід іде в сторінку, кроки не пишуться — напр.
   пройти Cloudflare руками), ⏳ наступний клік чекає відповідь, ↕ записувати скроли, 🔍
   підсвітка під курсором (`/inspect`), ⌨ клавіатура і ⤢ «1:1» (лише < 900 px); 📎 файл,
   ↶ видалити останній підтверджений, ⟲ відновити стан; ＋ Нова Дія (та сама сесія), ⏹ Готово.
4. **Ввід:** клік → ripple + рядок «…⏳» (pending) у списку → підтверджений крок v2 із ціллю
   (🎯/⚠/📍). Друк буферизується (показ inline) і йде одним `text` після 400 мс простою або
   перед кліком/клавішею/скролом; Enter/Tab/Esc/стрілки — `key`-кроки; Ctrl/Cmd+V — текст.
   Колесо збирається 120 мс в один `scroll`. `<select>` → поповер опцій; вибір файлу → ОС-діалог
   → `/upload` → `file`. Черга дій клієнта: одна в польоті, ≤ 10 в очікуванні.
5. **Кадр і маркери:** номери кліків — маленькі кільця з номером зліва-зверху (не накривають
   підпис кнопки); яскраві лише останні 3, старі бліді, накладені/застарілі (опція дропдауна під
   полем) прибираються (`pickMarkers`). Підказка «⌨ клавіатура (і Tab) → сторінка · Shift+Esc —
   вийти» — у кутку, на 3 с після фокуса кадру.
6. **Десктоп (≥ 900 px):** кадр вміщається у висоту панелі (зменшується бокс `<img>`, НЕ
   `object-fit` — мапінг кліків і оверлей рахуються від content-box), панель не прокручується,
   колесо над кадром іде лише в сторінку; консоль на час LIVE згорнута (після ⏹ — як була);
   сайдбар прокручується до Дії, що пишеться, і тримає новий рядок у полі зору
   (`followRecordingRow`; ручна прокрутка сайдбару призупиняє це, доки не повернешся до низу).
7. **Мобільний (< 900 px):** дотик + вузький екран → «1:1» за замовчуванням (збережений вибір
   `liveZoom1` має пріоритет), прокрутка — всередині перегляду; кадр дрібніший за 0.5 → раз за
   сесію банер «Дрібно? Увімкни 1:1» з кнопкою. Тап = клік, два пальці = колесо; під кадром —
   3 останні кроки (`.live-recent`); прихований `<input>` (`tabindex=-1`) піднімає екранну
   клавіатуру, коли ціль редагована.
8. **Збереження:** КОЖЕН підтверджений крок одразу → `page:changed` → `persist` (debounce 400 мс,
   злиття); на `pagehide` рекордер спершу ставить сценарій у чергу (keepalive-PUT), потім
   закриває сесію beacon-ом. Після перезавантаження вкладки — повернення до тієї ж Дії
   (`resolveReattach`): сесію закрито → банер «⟲ Відновити» (перевідкриває з префіксом).
9. **⏹ Готово / ⟲:** дочікуються дії в польоті до 75 с (≥ серверної межі дії 60 с) з банером
   «⏳ Чекаю завершення дії… [⏹ Закрити все одно]»; якщо перервано — явне попередження, що крок
   міг виконатись на сайті, але не записаний (без мовчазної втрати сабміту). ⟲ — single-flight
   (повторний клік не відкриває другу сесію й не відтворює префікс двічі). Події клієнта сесії
   приймаються лише від поточного клієнта. Порожня нова Дія не зберігається; фокус після ⏹ —
   на таб доданого скріна (інакше «⏺ Записати»). Видалення кроку з сайдбару під час запису →
   підказка «⟲ Відновити стан».

### Кроки v2, редактор, прогін
- **Крок v2** (див. «Живий запис і кроки v2»): семантична ціль `target.locs[]` (testid → role+name
  → label → placeholder → `[name]` → `#id` → текст → CSS з `nth`), `pick`, + координати документа
  `x/y/sw/sh` як **запасний шлях**: не знайдено за `timeout` → 📍 координати / 🧲 snap.
  Чип здоровʼя в рядку: 🎯 унікальний семантичний (або **стабільний CSS**: без nth, n=1, лише
  стабільні класи/id і якір на самому елементі чи батькові — `isStableCss`), ⚠ інший CSS/nth/
  кілька збігів, 📍 лише координати. Редактор ✎ показує кандидати НОРМАЛІЗОВАНОЇ цілі
  (мігровані `input[type=file]` та очищений CSS теж можна обрати).
- **Рядок кроку** (`scenarios.js` + `stepEditor.js`): іконка + `stepLabel` + чип + після прогону
  бейдж стратегії (🎯 / 🔁 alt + 🩹 / #nth / 📍 / 🧲 · мс); ✎ редактор у **модалці**
  (`openStepEditor` → `<dialog class="step-modal">`, заголовок «Крок N · «Дія»», підзаголовок —
  підпис + чип здоровʼя; Esc/✕/фон/«Скасувати» — без змін, «Зберегти» валідує, фокус
  повертається на ✎; < 600px — на весь екран): кандидати з ×n, «📍 лише координати» = `pick:-1`,
  текст із чипами `{d}`/`{l}`, ⏳ чекати відповідь, необовʼязковий, таймаут, «Пауза після
  кроку, мс»; ⏸ вимкнути, ↑↓, ✕ (з «Скасувати»). Legacy-рухи — «+N рухів».
- **Пауза після кроку** — поле кроку `delayAfter` (мс, 0..60000, `delayAfterMs`/`formatDelay` у
  `lib/steps.js`): додаткова пауза ПІСЛЯ виконання кроку (і після останнього, перед фінальним
  скрином); не діє для вимкненого/пропущеного кроку; Stop перериває. Лог «⏱ Пауза N мс після
  кроку #k», подія стріму `{event:'pause', index, ms}` → смуга «⏱ «X» · пауза 1,5 с після кроку
  2/5 — далі: …», чип рядка «⏱ +1,5 с · пауза…» (тимчасове поле `pausing`). Чип у рядку — «⏱ +1,5 с».
- **⤵ Обʼєднати текст** (`canMergeText`/`mergeTextSteps` у `lib/steps.js`): на текстовому кроці,
  якщо наступний ВИДИМИЙ крок (приховані рухи пропускаються) — теж текст. Неактивна з причиною
  (різні поля, вимкнений, ще виконується). Результат — крок v2: `text` = шаблон(a)+шаблон(b)
  (legacy-символи екрануються, рандом → `{d}`/`{l}`), ціль — від a (або b), `delayAfter` — від b,
  решта прапорців — від a. Пауза a (між двома введеннями) прибирається — про це кажуть підказка ⤵
  і тост (`droppedDelay`). Масове злиття `mergeTextRuns` (⚡) навпаки НЕ зливає через паузу.
- **Прогін** (`runner.js`): над переглядом смуга «▶ Виконується «X» · крок 3/8 · Дія — підпис»,
  попередній скрін притлумлено. Підсумок «успішно N, помилок M (крок K у «Дія»: …), ⚠ запасним
  шляхом (📍/🧲): F, пропущено, 🔁 виправлено локаторів» — крок, що мав робочий локатор, але
  пройшов за координатами/snap, — **не чистий ✓**: рядок ⚠, у заголовку Дії «· ⚠F», статус
  прогону `degraded` (⚠ на картці й табі). Після прогону Дії зі збоями/⚠ розгортаються, перший
  такий рядок — у полі зору (failShot, швидкі виправлення «📍 лише координати»/«необовʼязковий»).
  Збій до першого кроку (URL недоступний) → «Не вдалося відкрити URL: Сторінка недоступна
  (ERR_…) — url» (без «помилок 0») і картка помилки в переглядачі з «⟲ Повторити».
- **Undo-тости** («Скасувати» після видалення кроку/Дії/сценарію, ⚡ оптимізації, ⤵ злиття): ≥ 10 с,
  таймер на паузі, поки курсор/фокус на тості; під час прогону/запису скасування відхиляється
  (`guardUndo`), а відкриті тости закриваються. Відкат ⤵/⚡ відмовляє, якщо Дію відтоді змінено
  (перестановка/видалення/✎/додавання мутують `rec.subs` на місці, тож порівнюється не лише
  масив, а й поелементний вміст — `subsStamp`/`subsUnchanged` у `scenarioModel.js`).
  Видалення Дії з ≥ 4 кроками — з підтвердженням.

### Доступність
Справжні `<button>` з `aria-label` для іконок, `:focus-visible`, Esc закриває діалоги/меню;
меню ⋯ повертає фокус на якір (і діалоги з меню — теж), Tab із меню йде далі від якоря;
після видалення фокус — на сусідній рядок/Дію/сценарій. Живий кадр (`role=application`):
старт мишею — фокус на кадр, з клавіатури — на ⏹ Готово (щоб Tab не записався кроком);
Shift+Esc виходить і з кадру, і з IME-поля; фокус у полі видно рамкою кадру (`:focus-within`).

**Відомі обмеження:** перезавантаження вкладки під час запису закриває живу сесію (sendBeacon) —
кроки збережено, далі «⟲ Відновити» (префікс відтворюється заново); ⏹ Готово додає таб з
останнім viewport-кадром (fullPage-знімка живої сесії немає); «з початку» додає нову Дію в КІНЕЦЬ.

## Конфігуратор, опції та пресети

Модалка (⚙) має **ліве сайд-меню категорій** + праву панель. Усе зберігається в
профілі (`profile.json`) і застосовується через `POST /profile` (зміна launch-опцій
= перезапуск браузера). **Нічого анти-детектного не захардкоджено** — кожен важіль
вмикається/вимикається.

### Категорії та всі опції
- **⭐ Пресети** — набори в один клік (див. нижче).
- **🧩 Рушій** — radio **Chromium** (за замовчуванням) / **Camoufox**; + опції Camoufox:
  `camoufoxHumanize`, `camoufoxGeoip` (діють лише в режимі Camoufox).
- **🚀 Запуск** (`launch.*`) — `headless`, `newHeadless` (--headless=new vs старий),
  `automationControlled` (--disable-blink-features), `realGpu` (ANGLE Metal),
  `siteIsolationDisabled` (чекбокс «вимкнути ізоляцію сайтів»), `stealthPlugin`, `persistent`.
  **Зміна поведінки:** раніше ізоляцію сайтів вимикали ЗАВЖДИ (прапорець ігнорувався);
  тепер `siteIsolationDisabled:false` реально вмикає ізоляцію — крос-доменні iframe
  (Ashby) можуть зникнути з fullPage-скрину. Профіль без поля = як раніше (вимкнено).
- **🕵️ Stealth** (`stealth.*`) — `webdriver`, `windowChrome`, `outerWindow`,
  `permissions`, `pwInitScripts`.
- **🧍 Поведінка** (`behavior.*`) — `humanize` (людські рухи/затримки/друк по буквах —
  у /replay, у префіксі живої сесії і в її діях click/text/key), `prepareScroll` (autoScroll
  перед відтворенням legacy-координатних кліків, див. «Координати…»), `fastPrefix`
  (префікс живої сесії без humanize — швидше; логується). Рішення — `behaviorOpts`
  (`lib/human.js`), застосоване — у лозі контексту («🧍 Поведінка: …»).
- **🧬 Fingerprint** — UA, locale, timezoneId, platform, vendor, hardwareConcurrency,
  deviceMemory, deviceScaleFactor, screen (w/h/colorDepth). Автозахоплення fingerprint з
  браузера UI НЕ спрацьовує в автоматизованому браузері (`navigator.webdriver` / Headless UA —
  `isAutomatedBrowser` у `public/js/config.js`), щоб тести/headless не записали свій відбиток.
- **🍪 Cookies** — лічильник + очищення.

Draft-модель: значення не губляться при перемиканні категорій; «Зберегти» застосовує.

### 📤 Експорт конфігу (для Claude / власного клієнта)
Кнопка **📤 Експорт** у футері конфігуратора → `GET /profile/export` (`?preset=&status=`;
`?format=json` — лише специфікація) → Markdown `stealth-config-<пресет|custom>-<локальна дата>.md`.
Експортується **ЗАСТОСОВАНИЙ** конфіг (незастосовані зміни — лише тост-попередження); під час
застосування кнопка вимкнена. Генерує чиста `buildConfigExport` (`lib/exportConfig.js`).
- **Що всередині:** таблиця «Коротко»; як застосунок використовує конфіг (порядок init-скриптів:
  контекстний — ПЕРШИМ, евейжни плагіна — після; `user-agent-override` перекриває
  `CONTEXT.userAgent`; ізольований світ для зондів; /render і /replay; паузи/роздивляння);
  де застосовується кожне поле fingerprint; JSON-специфікація (launch/context/stealth/
  fingerprint/expected, версії лише потрібних пакетів); **дослівний** init-скрипт; готовий
  `client.mjs`; слабкі місця конфігу; як перевірити.
- **`client.mjs`** містить рантайм застосунку **дослівно** (`String(fn)` з `lib/isoworld|nav|dom|
  settle|human|replay.js` — `runtimeSource()`), тож поведінка не розходиться; браузерні пакети
  імпортуються динамічно; stealth-плагін реєструється раз на процес; Camoufox — сам латає
  валідатор camoufox-js 0.10.2 (`patchCamoufoxJs`, той самий шаблон, що postinstall).
- **Без секретів:** значення cookies, storageState і localStorage НЕ експортуються — лише
  кількість і домени.
- **Як перевірити:** відкрити ту саму **власну** сторінку-детектор (напр. `test/fixtures/signals.html`
  через локальний сервер) у застосунку (рендер) і `node client.mjs <url> out.jpg --signals` —
  сигнали Chromium мають збігатися повністю; у Camoufox fingerprint (ОС, екран, WebGL, ядра)
  випадковий на кожен запуск — збігаються лише структурні сигнали. Тести: `test/exportConfig.test.js`,
  e2e `E2E=1 node --test test/e2e/export.e2e.test.js`.

### 📦 Експорт / імпорт пресетів і сценаріїв (перенесення між машинами)
Не плутати з 📤 Експортом конфігу (Markdown) вище. Файл `stealth-bundle-<presets|scenarios|all|назва-одного>-<дата>.json`:
`{format:'stealth-render-studio/bundle', version:1, exportedAt, presets:[{name, body}], scenarios:[{name, url,
recs:[{name, subs}]}], files:[{fileId, filename, size, data:base64|null, missing?, skipped?:'too_large'|'excluded'}]}`.
- **Чисто:** без id пресетів/сценаріїв/Дій (на імпорті — нові), без builtin, без runtime-полів (те саме правило,
  що `pagePayload`: `stripTransient`, кроки `pending` — геть); id КРОКІВ лишаються. Профіль/cookies НЕ експортуються.
  **Тіло пресета — білий список** `PRESET_BODY_KEYS` (`launch`/`stealth`/`behavior`/`fingerprint`/`clear:true`) і на
  експорті (`cleanPreset`), і на імпорті (`parseBundle`; відкинуте → попередження «поля … проігноровано»): cookies/
  storageState з чужого файлу інакше потрапили б у профіль через `applyProfilePatch` (чужа сесія / стерті cookies).
  **Текст кроків (зокрема введені паролі) іде у файл як є** — діалог експорту це каже і попереджає, якщо ціль
  текстового кроку схожа на поле пароля (`secretTextSteps`, евристика за описом/локаторами: тип поля не зберігається).
- **Файли** кроків `type:'file'` вибраних сценаріїв — base64, сумарно ≤ `EXPORT_FILES_MAX_BYTES` (50 МБ); більше →
  `skipped:'too_large'`, немає на диску → `missing:true`, `files=0` → `skipped:'excluded'` (крок потребуватиме
  перевибору файлу). На імпорті клієнт сам вантажить вкладені файли через `/upload` (лише для сценаріїв, що
  створюються/замінюються) і робить `remapFileRefs` — новий fileId, той самий вміст.
- **Конфлікти** (`planImport`, назви через `normName`, регістр враховується): та сама назва + однаковий зміст
  (пресет — `body`, сценарій — `{url, recs[{name, subs}]}`, без порядку ключів) → пропуск «= такий самий»
  за будь-якої стратегії; інший зміст → стратегія блоку: **Перейменувати** (за замовч., `uniqueName`: «X (2)»,
  продовжує « (N)», обрізає основу) | **Замінити** (перший з такою назвою; сценарій — той самий id) |
  **Пропустити**. Дубль назви всередині файлу → завжди нова назва (`duplicate_in_bundle`).
  Ліміти назв: пресет 80, сценарій 200 (як в UI).
- **API:** `GET /export?presets=<ids|all>&pages=<ids|all>&files=0|1` (без обох — усе; Content-Disposition з
  `filename*`); `POST /import {bundle, select?:{presets?, scenarios?: індекси}, onConflict?:{presets?, scenarios?},
  dryRun?}` → `{ok, dryRun, db, presets:[план + id?], scenarios:[…], warnings, summary}`. Сервер авторитетно
  перевалідовує (`parseBundle`: формат/версія/типи/ліміти, без `__proto__`, символ NUL `\u0000` будь-де → 400 —
  Postgres його не приймає) і перебудовує план проти ПОТОЧНОГО стану; імпорти — строго по черзі; ліміт тіла 20mb
  лише на цьому роуті; 400 — людський текст. Запис — ОДНІЄЮ транзакцією (`db.tx` = `withTransaction` у `lib/db.js`):
  збій посередині → 500 і нічого не записано. Без БД пресети → `skip` `no_db` + попередження, сценарії — у памʼять
  процесу (лише після побудови всіх записів).
- **Replace і «такий самий»:** елемент файлу порівнюється лише з існуючими, які НЕ перезаписує вже запланований
  replace (бандл `[X{a}, X{b}]` проти існуючого `X{b}` → replace + «X (2)» з `{b}`, а не пропуск — інакше `{b}` зник би).
- **UI** (`public/js/transfer.js`): хедер (верхнє меню) `#importBtn` / `#exportBtn` — увесь застосунок (експорт: УСІ пресети + УСІ сценарії вибрано наперед); меню ⋯ сценарію «📤 Експортувати
  сценарій» (одразу файл); конфігуратор — `#cfgPresetsExport` / `#cfgPresetsImport` у рядку пресетів. Експорт:
  чекбокси «Пресети»/«Сценарії» з «усі / жодного», «Включити файли кроків (N)», порожній вибір → кнопка вимкнена з
  поясненням. Імпорт: файл (кнопка або drag&drop) → прев'ю з чипами плану («новий», «= такий самий є — пропуск»,
  «конфлікт назви → «X (2)»», «замінить існуючий», «пропуск», «БД недоступна — пропуск»), radio-стратегія на блок,
  миттєвий перерахунок; під час прогону/запису імпорт вимкнено; перед ним — `flushAllPages()` і перевірка
  `flushProblem(persistStatus())`: якщо PUT /pages падає (напр. 413 на великому сценарії) — імпорт НЕ починається
  («спершу «Не збережено · повторити»»), бо `loadPages()` після нього затер би локальні правки. Експорт у такому разі
  попереджає тостом, що у файлі остання ЗБЕРЕЖЕНА версія. Після імпорту — тост `summary`, лог, `loadPages()`,
  `presets:changed` (лише якщо пресети створено/замінено; конфігуратор повертає фокус на той самий контрол),
  фокус на першому імпортованому сценарії. Збій POST /import з 5xx/мережею/таймаутом (`importMayHaveWritten`) →
  `loadPages()` + перечитані пресети + алерт «міг виконатися частково»; вже завантажені файли кроків кешуються в
  межах діалогу (повтор не створює нових fileId). Під час імпорту вміст діалогу `inert` (вибір/стратегія —
  знімок `importSnapshot` на старті), діалог не закривається навіть подвійним Esc (перевідкривається), файл,
  кинутий будь-куди в діалог, не відкривається браузером. Перерендер списків зберігає їхню прокрутку.
- **Обмеження:** сценарій із кроком file після імпорту має НОВИЙ fileId, тож повторний імпорт того самого файлу
  вже не визнає його «таким самим» (конфлікт назви → стратегія). Без БД пресети не переносяться.
- **Тести:** `test/transfer.test.js` (ядро), `test/transfer.routes.test.js` (роути, фейкова БД, tmp uploads),
  `test/transfer.ui.test.js` (чиста логіка UI), e2e `E2E=1 node --test test/e2e/transfer.e2e.test.js`
  (справжній `node server.js` без БД: експорт download-ом, імпорт з конфліктом/пропуском/заміною, 390×844,
  надійність: drop повз зону, прокрутка, inert/подвійний Esc, 500 → перечитаний список, збій збереження, фокус).

### Пресети (калібровані)
(Вбудований пресет «🛡️ All» прибрано — максимальний стелс збирається вручну або через 📋 Ashby.)
- **Видалення ✕** — на кожному пресеті (і вбудованому теж) кнопка ✕ з підтвердженням →
  `DELETE /presets/:id` (404, якщо вже немає). Профіль браузера НЕ змінюється; видалено
  активний → режим «кастом». Вбудовані пресети засіваються ОДИН раз (прапорець
  `app_meta.presets_seeded`), тож видалені не повертаються. Якщо видалено активний «голий»
  пресет (`clear` / `fingerprint:null`), у localStorage ставиться `noAutoFp=1` — автозахоплення
  fingerprint при наступному завантаженні UI не спрацює (вибір будь-якого пресета знімає заборону).
  Фокус після видалення — на ✕ сусіднього пресета.
- **Перейменування ✎** — кожен пресет — група `[чип][✎][✕]`. ✎ → діалог із поточною назвою →
  `PUT /presets/:id {name}`. Валідація (клієнт `presetNameError` + сервер `validatePresetName`):
  пробіли обрізаються/стискаються, 1..80 символів, без дубля іншого пресета (та сама назва — без
  запиту). 404 → червоний алерт. Профіль браузера НЕ змінюється; активний лишається активним
  (чип — нова назва). Сфокусована кнопка групи піднімається `z-index`, щоб focus-ring не
  перекривав сусід.
- **Збіг із пресетом не залежить від порядку ключів** (`stableJson`/`sameValue`): Postgres
  JSONB переставляє ключі, інакше збережений пресет показувався «● змінено».
- Кнопки «🧹 Скинути до голого Playwright» у футері більше немає — застосуй пресет «Clear all»
  (якщо його не видалено).
- **🧹 Clear all** — усе вимкнено = голий дефолтний Playwright (webdriver=true, без
  stealth, без fingerprint, старий headless, без GPU-флагів, **ізоляція сайтів УВІМКНЕНА**,
  без humanize і без autoScroll перед відтворенням).
  Власні пресети, збережені після «Clear all», містять `siteIsolationDisabled:false` — для
  Ashby-подібних форм збережи їх наново з увімкненим чекбоксом ізоляції.
- **☁️ Cloudflare** — **лише `engine: camoufox`**. Калібровано: Camoufox проходить
  rubyonremote навіть БЕЗ humanize/geoip. Chromium (навіть із усім) не проходить.
- **📋 Ashby** — Chromium + повний стелс + `siteIsolationDisabled` (щоб крос-доменний
  iframe Ashby рендерився у скрині) + humanize. Перевірено одним прогоном Сценарію 1:
  фінальний скрін показав зелене «Success — Application received».

### Калібрування (емпіричні результати)
- **Cloudflare (rubyonremote):** мінімум = Camoufox. `camoufoxHumanize`/`camoufoxGeoip`
  НЕ потрібні (перевірено — проходить і без них).
- **Ashby (Preply apply):** повний Chromium-стелс + вимкнена ізоляція сайтів проходить
  анти-спам (зелене повідомлення). Глибше звуження не калібрувалось: кожен прогін —
  РЕАЛЬНА відправка заявки в ATS третьої сторони (етичне обмеження, не спамимо).
- **Перекалібрувати:** обидва результати вище виміряні ДО появи підготовчого autoScroll
  у /replay (`behavior.prepareScroll`, увімкнено за замовчуванням для legacy-кліків) і
  до переносу зондів в ізольований світ. Перевір із `prepareScroll` увімк/вимк (Ashby —
  без реальної відправки: зупинитись перед кроком сабміту).

## Антидетект: що працює і ЧОМУ (головні висновки сесії)

Цей розділ — суть того, що з'ясовано експериментально про детектування автоматизації.

### Рівні сигналів (від простих до непереборних у headless)
1. **Задекларовані** (UA, мова, таймзона, екран) — легко підставити (fingerprint).
2. **Наш stealth** (`stealthScript`): `navigator.webdriver=false` НА ПРОТОТИПІ (не
   own-property!), повний `window.chrome`, `outerWidth/Height`, видалення
   `window.__pwInitScripts`, узгоджений `permissions.query`.
3. **stealth-plugin** (puppeteer-extra): плагіни, WebGL та десятки патчів.
   `webgl.vendor`-евейжн ВИМКНЕНО — бо вмикаємо реальний GPU (див. нижче).
4. **Поведінка** — рухи/затримки/друк по буквах/скроли.
5. **CDP-керування** — Chromium керується через CDP, і це детектується (витік
   `Runtime.enable`). Приховати init-скриптом НЕ можна (це канал керування, а не
   сторінка). Патчиться лише на рівні драйвера (`rebrowser-patches`/`patchright`).
6. **«Живий» рендер** — Canvas/WebGL реальним GPU. Увімкнено апаратний GPU на Mac:
   `--use-gl=angle --use-angle=metal` → реальний Apple-рендер замість софтверного
   SwiftShader. Назву WebGL НЕ спуфимо (щоб не суперечити реальним пікселям).
7. **Репутація IP** — резидентний проходить, дата-центр (VPN/Hetzner) блокується ЖОРСТКІШЕ.
8. **Зонди відтворення в головному світі** — `page/frame/locator.evaluate` у Chromium
   виконуються в світі сторінки: її обгортки над `querySelectorAll`/`elementFromPoint`/
   `getComputedStyle`/`getBoundingClientRect`/rAF бачать виклик зі стеком
   `UtilityScript.evaluate` (підпис Playwright). Тому всі read-only зонди відтворення
   (`lib/dom.js`: measure, hit-test, snap, фокус, нейтральна точка, scroll-settle; `lib/nav.js`:
   content-settle, текст фреймів, Cloudflare-перевірка, autoScroll) йдуть у **приватний
   ізольований світ** через CDP (`lib/isoworld.js`: `Page.createIsolatedWorld` +
   `Runtime.evaluate` з contextId, БЕЗ `Runtime.enable`; дочірні фрейми — `DOM.describeNode`,
   out-of-process iframe — окрема сесія). `locator.evaluate`/`elementHandle.evaluate` —
   НЕ безпечні (головний світ). Camoufox: CDP немає → `frame.evaluate` (там і так ізольовано).
   Регресійний тест: `test/e2e/mainworld.e2e.test.js` (0 викликів обгорток). Ще не
   перенесено: захоплення цілі в живій сесії (`lib/capture.js`), фінальні метрики /replay, /render.

### Ключові відкриття про Cloudflare
- **`window.__pwInitScripts`** — Playwright створює цей об'єкт на сторінці через
  `addInitScript`. Це прямий підпис Playwright. Прибирається видаленням об'єкта в
  кінці init-скрипта (ми це робимо).
  **Уточнення (Playwright 1.63):** об'єкт НЕ створюється взагалі. Раніше опція ставила
  на нього геттер, і `'__pwInitScripts' in window` ставало `true` (у Chrome — `false`) —
  сама додавала сигнал. Виправлено: опція лише видаляє об'єкт, якщо він є.
  ✅ Калібрування пресетів перевірено після виправлення (2026-10-06): працює.
- **`navigator.webdriver`** має бути `false` (а не `undefined` і не own-property).
  Наш спуф на прототипі — щоб `Object.getOwnPropertyNames(navigator)` був чистий.
- Перевірка стелсу: **https://bot-detector.rebrowser.net** — ми довели 3/3 зелені
  (runtimeEnableLeak, navigatorWebdriver, pwInitScripts) для Chromium + реальний GPU.
- **АЛЕ Cloudflare на деяких сайтах (rubyonremote) блокує навіть при 3/3 зелених і
  реальному GPU — і навіть у headful.** Висновок: він детектує сам факт керування
  фреймворком (Chromium/CDP) + середовище, а не лише JS-сигнали. Chromium тут
  непрохідний жодними нашими засобами.
- **Переможне рішення — зміна рушія на Camoufox (Firefox).** Firefox керується
  протоколом Juggler, а НЕ CDP → увесь клас CDP-детекції Cloudflare не застосовний.
  Fingerprint вшитий у C++ рушія, тож JS-слідів немає. Camoufox ПРОХОДИТЬ rubyonremote.

### Що таке Camoufox (важливо не плутати)
- **Playwright** = драйвер (керує браузером). Багатодвигунний: Chromium→CDP,
  Firefox→Juggler, WebKit→свій протокол. Один API — різні «перекладачі» всередині.
- **Camoufox** = браузер (кастомна збірка **Firefox**), аналог Chromium, НЕ Playwright.
  Будується поверх Firefox-збірки Playwright (з Juggler) + антидетект-патчі в C++.
  `camoufox-js` каже Playwright: `firefox.launch({ executablePath: <camoufox> })`.

## База даних

- `pages(id BIGINT PK, name, url, recs JSONB, created_at, updated_at)` — Сценарії з
  вкладеними Діями (recs) та під-діями (subs у JSONB).
- `recordings(...)` — legacy-таблиця (стара пласка модель Дій), лишена для сумісності.
- Під-дії **v2** (живий запис) лежать у тих самих `recs[].subs` — без міграції:
  `{id, v:2, type, target:{frame, locs[], pick, rel, box, tag, kind, desc}, x, y, sw, sh, …}`
  (див. «Живий запис і кроки v2»). Під-дія без `v` і без `target` = legacy (координати).
- Таблиці створюються автоматично при старті (`initDb`).

  яких немає в `properties.json`, і валідатор падає. `scripts/patch-camoufox.mjs`

## Відкинуті підходи (і чому)
- **rebrowser-patches / patchright** (приховування CDP) — закривали CDP-витік
  (детектор зеленів), АЛЕ rubyonremote все одно блокував, і вони вимагають
  playwright-core 1.52, що конфліктує з Camoufox (1.63). Прибрано на користь

## Живий запис і кроки v2 (локатори)

Замість запису на статичному скрині — **жива сесія**: сервер тримає відкриту сторінку
(власний контекст, НЕ з пулу), клієнт бачить viewport-скриншоти й шле дії.

**API** (`routes/live.js`, логіка `lib/live.js`, стан `lib/session.js`):
- `POST /live {url, actions, recId}` → NDJSON: `session` → `log`/`status`/`action`/`done-action`
  (префікс `actions` відтворюється тим самим `runSteps` з `behavior.humanize` — швидкий лише з
  `behavior.fastPrefix`; таймаут кроку 2.5 с; збій кроку не зупиняє — сесія відкривається у
  досягнутому стані) → `{event:'live', sid, engine, vp:{w,h,dpr,scrollX,scrollY,docW,docH},
  shot, hash, url, title}` або `{event:'error'}` (сесію закрили під час відкриття — relaunch,
  DELETE, закриття сторінки — → `{event:'error', code:'session_closed', reason}`).
  Дії click/text/key теж шанують `behavior.humanize` (людський рух + роздільні down/up з
  паузою, друк по буквах, клавіша з delay).
- `POST /live/:sid/act {type: click|dblclick|text|key|scroll|file|select, vx, vy, text, key,
  dx, dy, fileId, filename, value, rec, waitResponse, k, h}` → `{ok, k, step, shot?, hash, vp,
  url, title, ms, logs, needFile?, needSelect?, configChanged}`. `step` = null при `rec:false`;
  `shot` лише якщо хеш змінився (відносно `h`). Помилка дії → `ok:false` + знімок (200),
  валідація → 400. Клік по нативному `<select>` НЕ клікає — `needSelect.options`, далі act
  `select`. Відкрився вибір файлу → `needFile`, далі `/upload` + act `file`.
  `text` — шаблон (`{d}`, `{l}`, `{{`): на сторінку йде розгорнутий, у крок — як є.
- `GET /live/:sid/shot?h=` — keep-alive + скрин лише при зміні хешу.
  `POST /live/:sid/nav {action: goto|back|forward|reload, url}`.
  `GET /live/:sid/inspect?x&y` → `{box, target, desc}` без кліку.
  `POST /live/:sid/run {steps}` → NDJSON через спільний `runSteps` («▶ спробувати»).
  `POST /live/:sid/close` (sendBeacon) і `DELETE /live/:sid`. `/health` має `sessions`.
- Закрита/невідома сесія → **410** `{code:'session_closed', reason}` (причини живуть 10 хв;
  запит, що був у польоті, коли сесію закрили — `/shot`, `/act`, `/inspect`, `/nav` — теж 410, а
  не 500 з «Target page… closed»); тексти помилок у JSON/NDJSON — без ANSI і «Call log» (`cleanError`);
  поки відтворюється префікс → **409** `session_busy`; третя сесія → **429** (або витісняється
  найстарша, що простоює > 60 с); немає слота за 15 с → 503; черга дій сесії > 20 → 429
  `session_queue_full`; дія не вклалась у межу (act 60 с, inspect 15 с, nav 120 с; `run` —
  без межі, має власне переривання) → **504** `act_timeout` і сесію ЗАКРИТО (dispose контексту
  відхиляє завислі Playwright-виклики; сторінка з заблокованим головним потоком більше не
  тримає слот і контекст вічно). `sweep` теж закриває зайняту сесію, що пережила межу.

**Життєвий цикл** (`SessionStore`): max 2, простій 5 хв (sweep кожні 30 с, unref-таймер),
дії однієї сесії — строго по черзі (`run(sid, fn)`). Закриття: клієнт, простій,
`page close/crash`, **relaunch браузера** (`onBeforeRelaunch` → `closeAll('config changed')`),
SIGTERM/SIGINT. `drainPool` сесій не чіпає — замість цього `configChanged:true` (`profileSig`).
Попап → стає сторінкою сесії; діалоги приймаються (лог).

**Захоплення цілі** (`lib/capture.js`): `hitTest` — найглибший фрейм за геометрією, крізь
відкриті shadow root, підйом до найближчого інтерактивного предка; `DESCRIBE_FN` лише
ЧИТАЄ DOM (у **Camoufox `evaluate` працює в ізольованому світі** — глобали сторінки
недоступні, лише DOM-API) і повертає `ElementDesc` (`lib/locators.js`); `describeFrameChain`
→ `target.frame = {chain:[css <iframe> ззовні всередину], url-глоб, path, name, index}`;
`countCandidates` — `count()` локаторів Playwright (≤6, бюджет 400 мс). CSS-кандидат з
кількома збігами отримує `nth` (збіг під точкою). `target.box` і `x/y` кроку — у CSS px
**документа головної сторінки** (для iframe теж), `sw/sh` = scrollWidth/Height → старий
координатний шлях розуміє крок v2 (масштаб ≈ 1).

**Відтворення кроку з target** (`lib/replay.js`, спільне для `/replay`, префікса і `/run`):
фрейм — ланцюг `frameLocator` (кожен селектор рівно 1 збіг), інакше `matchFrame` за
origin+path → URL-глоб → name → index (опитування 250 мс); кандидати `[pick, …решта]`
кожні 200 мс до `step.timeout` (6 с). Рівно 1 збіг → `loc` (або `loc-alt` + `healed`, якщо не
pick); кілька → найближчий до `target.box` → `nth` (CSS+nth рахує базовий селектор —
індекс міг змінитись). Клік: humanize — `click({trial})` (actionability + scrollIntoView) →
бокс → точка `rel` ±15% → людський рух → бокс перечитується (зсув > 4px → корекція) →
down/up; без humanize — `locator.click({position})`. Текст — фокус-клік лише якщо
`needsFocusClick`; `clear` → ControlOrMeta+a, Backspace; ніколи `fill()`. Select — value,
потім label. File — `setInputFiles` на ціль (інакше input за порядком). Не знайдено →
координатний шлях (`coord`/`snap`, лог «🎯→📍 локатор «…» не знайдено за N с»); `optional` →
`skipped`; збій → `done-action.failShot` (viewport jpeg q50). Далеко (> 400px) від запису →
попередження в лозі. Legacy-кроки (без target) — без змін (розділ нижче).

**Автопокращення цілі після успішного прогону** (`upgradeCandidates` у `lib/steps.js`,
`findUpgrade` у `lib/replay.js`): якщо pick слабкий (⚠), а крок знайдено надійним локатором
з 1 збігом — pick переходить на нього; інакше перевіряються інші надійні кандидати
(`count()===1` і `l.and(found).count()===1` — той самий елемент, через selector-engine).
Результат — `done-action.upgrade={idx}` (лише ok і не skipped) + лог «🎯 Ціль … стане
надійнішою», `runner.js` оновлює збережений крок і зберігає (`page:changed`). Обмеження:
pick, що вже 🎯 (надійний, n=1), ніколи не міняється (разовий 🔁 через повільний рендер — не
привід); збіг > 400px від запису — без покращення. **Міграція** (`normalizeStep`): старі
file-кроки отримують `input[type=file]`; перед CSS-шляхом із хеш-класами (CSS-модулі,
напр. Ashby `_container_f7cvd_28`) вставляється очищена копія (`stripUnstableClasses`), лише
якщо вона `isStableCss` — тож Ashby переходить на `div#form > div.ashby-…-uploader > … > input`.

## Координатний шлях відтворення (legacy-кроки і запасний 📍/🧲)

Сьогодні нові кроки пишуться живим записом (координати — CSS px документа, масштаб ≈ 1). Старі
кроки (без `v`/`target`, записані колись на fullPage-скриншоті — пікселі = CSS × DPR) і
запасний шлях кроків v2 (локатор не знайдено) відтворюються координатами. Надійність цього
шляху — P0-фікси причин «клік спрацьовує через раз»:

- **Масштаб** міряється ПЕРЕД кожною дією: `a.dpr` → `1/dpr`; `a.sw` → `recordScale`
  (відношення `sw / scrollWidth` «прилипає» до типового DPR, тож 15px скролбару —
  1265 vs 1280 при `--hide-scrollbars`/Camoufox — не дає дрейфу +35px по Y). Старі
  записи без `sw` — простір по Дії (`gid`): макс. X > viewport → device-простір → ÷DPR.
- **Підготовка сторінки** як у /render: `prepareForInteraction` (settle + autoScroll
  + назад угору) перед першою дією — lazy-контент має ту саму висоту, що на скрині.
  Лише якщо є legacy-координатні click/move (`needsLegacyPrep`, `lib/steps.js`; спільне
  правило /replay і префікса /live) і `behavior.prepareScroll` не вимкнено; інакше —
  лише settle контенту (лог «⏭ autoScroll пропущено (причина)»). У /replay режим
  `replay`: без мутацій DOM (`loading='eager'`/`data-src` лише в /render); з humanize —
  колесом миші (`wheelSweep`: нейтральна точка, порції 60–90% viewport, назад порціями).
- **Скрол** лише якщо ціль поза безпечною смугою (`scrollPlan`, margin 80px, з
  урахуванням фіксованих шапки/футера `topInset/bottomInset`), `scrollTo({behavior:'instant'})`
  (перекриває CSS smooth без зміни стилів — stealth) і очікування, доки `scrollY`
  однаковий 2 кадри (`waitScrollSettle`). **Рухи миші не скролять** (точка поза
  viewport → рух пропускається).
- **Фіксований елемент** у першому екрані скрину (cookie-банер, шапка): якщо в точці
  `(x, docY)` поточного viewport інтерактивний **fixed** — клік без прокрутки (за будь-якого
  scrollY); **sticky** — лише при scrollY = 0 (прилиплий сайдбар на прокрученій сторінці
  інакше перехопив би клік першого екрана; `preferFixedHit`).
- **Повторний hit-test прямо перед `mouse.down`** (після руху; `scrollY` перечитується
  — scroll anchoring/догрузка). `classifyHit` → `interactive` (closest(`INTERACTIVE_SEL`),
  ролі, contenteditable, label, cursor:pointer, клас *option*) / `content` / `empty`;
  `decideSnap`: interactive → довіряємо, empty → snap ≤60px, content → snap лише ≤24px.
  Кандидати snap — лише видимі (не перекриті) контроли, без `aria-expanded=true`.
- **Після кліку/клавіші** — не фіксований сон: навігація головного фрейму →
  `domcontentloaded` + `waitPastCloudflare`; інакше `waitQuiet` (`lib/settle.js`: Node-side
  трекер request/requestfinished/requestfailed, ігнор запитів старших 3с; 150/300/2500 мс).
  Після файлу — `waitQuiet` + settle (чіп завантаження).
- **Роздивляння** (humanWander) — детермінований розклад `shouldWander`: після
  відкриття і кожен 4-й клік, НІКОЛИ після click/key/text (може бути відкритий попап);
  колесо — лише в нейтральній точці (не над скролером/списком/iframe), далі scroll settle.
- Діалоги приймаються (лог), попап/нова вкладка — дії переходять у неї.
- Текст: шаблон `{d}`/`{l}`/`{{` (`lib/textTemplate.js`), legacy `random` шанується.
- `/replay`: перша подія `{event:'run', runId}`; `POST /replay/:runId/stop` зупиняє
  (фінальний скрин буде); відʼєднання клієнта → стоп + негайне закриття контексту.
  Stop поки прогін чекає слот → очікувач виходить із черги семафора (`acquire` з
  `signal`) і потік закінчується `{event:'error', stopped:true}`. Stop посеред кроку
  (напр. поки шукається ціль) — жодного запасного координатного кліку/друку/файлу:
  крок обривається з `error:'зупинено'`, `aborted:true`.
  `done-action` має `{strategy:'coord'|'snap'|'loc'|'loc-alt'|'nth', ms, error, skipped?, healed?, failShot?}`.

Чиста логіка — `lib/coords.js` (`toDocCoords`, `recordScale`, `scrollPlan`, `classifyHit`,
`decideSnap`, `shouldWander`, …) і `lib/settle.js` (`waitQuiet`); браузерні частини
(`measure`, `scrollDocTo`, `elementAt`, `snapToClickable`) — `lib/dom.js`; цикл — `lib/replay.js`.
E2E на фікстурах кожної причини: `test/e2e/clicks.e2e.test.js` (N=5 прогонів на кейс,
`E2E_RUNS` змінює N).

## Тестування (обовʼязково)

- Запуск: `npm test` (вбудований `node:test`, без зовнішніх залежностей; без браузера, ~15 с).
  Один файл: `node --test test/liveModel.test.js`.
- E2E зі справжнім Chrome: `npm run test:e2e` (`test/e2e/*.e2e.test.js`, ~7 хв; без `E2E=1`
  вони пропускаються). Лише локальні фікстури (`test/fixtures/*.html`), жодних реальних сайтів.
  Поруч із робочим сервером: `TMPDIR=<тека> UI_TMP=<тека> UI_PORT=<не 3000> npm run test:e2e`
  (тимчасові profile/uploads — у `TMPDIR`/`UI_TMP`; БД не чіпається). Один файл:
  `E2E=1 node --test test/e2e/recorder.e2e.test.js`.
- Що покрито у фронтенді: чиста логіка — `test/liveModel.test.js` (координати, маркери, зум,
  `applyActResult`, `resolveReattach`, `undoIndex`), `test/liveClient.test.js` (черга, опитування,
  close після запитів у польоті), `test/scenarios.ui.test.js` (persist, план/підсумок прогону,
  `isFallback`, `nextRecName`, `guardUndo`, пауза тосту, follow сайдбару), `test/shell.test.js`
  (таби, смуга прогону, порожній стан), `test/errText.test.js`, `test/contrast.test.js` (токени ≥ 4.5:1).
  Браузерні: `recorder.e2e` (живий запис, вміщення кадру 1280/1024, ↶ у `/pages`, 390 px: «1:1»
  за замовчуванням і кнопка «⏺ Дописати» Дії, перезавантаження посеред запису), `ui.e2e` (повний
  потік), `scenarios.e2e` (прогін, статуси, редактор, undo).
- Інтеграційний UI-e2e (`test/e2e/ui.e2e.test.js`): запускає справжній `node server.js`
  (власний порт `UI_PORT` або вільний, без БД, profile/uploads у tmp; або `UI_BASE` — уже
  запущений ТЕСТОВИЙ сервер, ніколи не :3000) і веде UI в headless Chrome: діалог створення,
  живий запис (поле, асинхронний дропдаун, `<select>`, файл, submit в iframe —
  `test/fixtures/apply.html`), підписи з 🎯, `/pages`, ▶ усі ✓, зсунута верстка `?shift=1`,
  390×844, legacy-сценарій. `UI_SHOTS=<тека>` зберігає скріни `final-*.png`, `UI_HUMANIZE=1` — з людською поведінкою.
- Роути тестуються через `createApp` з фейковими engine/db (`test/app.routes.test.js`,
  `test/live.routes.test.js`); локаторний шлях відтворення — на фейкових локаторах
  (`test/replay.locators.test.js`); живий запис у справжньому Chrome — `test/e2e/live.e2e.test.js`.
- У `test/` не клади допоміжні `.js` — `node --test` запускає їх як тести.
- **Політика: кожен новий функціонал має бути покритий тестами.** Виноси чисту
  логіку в модулі (`lib/*.js`) і додавай тести у `test/*.test.js`.
- **Гейт перед commit і push**: git-хуки `.githooks/pre-commit` та `.githooks/pre-push`
  запускають `npm test` і блокують операцію, якщо тести впали.
  Увімкнено через `git config core.hooksPath .githooks` (після клону виконай цю
  команду одноразово, бо хуки не активуються автоматично).
